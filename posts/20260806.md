# Methodology-as-code requires one portable execution path


Core mathematics is TSC's semantic and warrant foundation, not a separate stage
that executes. Methodology-as-code is the platform boundary; Repository
Coherence is one package/application, not TSC's identity. The immediate
engineering path became:


`.cm -> normalized IR -> linking/plan -> runtime -> MeasurementReceipt -> verifier`.


The kernel must be constrained from both sides. An ordinary check-style CM must
prove usable product execution; Ascent-0 must prove that retained alternatives
and information barriers were not designed away. Retain typed
capabilities/evidence, principled `INCOMPLETE`, collection-valued evidence,
bounded deterministic fanout/fold, phases/barriers, observation versus derived
claims, independently recomputable receipts, and progressively stronger
obligations over one evidence model. Both ordinary execution and Ascent-0
reproduction gate ABI freeze.


Open: promote the converged architecture to a project-native document before
issue mutation or implementation dispatch. The one-way sequence “ordinary CM
first, Ascent later” and any claim that Core itself runs were superseded.
