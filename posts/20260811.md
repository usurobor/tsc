Operator strategy — schema-first, compiler deferred. Ratified 2026-08-11.

Operator: *"it probably doesn't make sense to focus on compiler just yet. We need
to be focusing on json schema and writing json files against it to implement
gradually increasing in complexity cases we run with coh. Knowing once that works
writing compiler is a straightforward exercise."*

I assessed this as correct and it is now the working spine. The reasoning that
makes it correct: the compiler is a front-end to a target, and the target is still
being *discovered* — the two-sided-kernel argument (converged with Pi) is that the
runtime ABI must be **learned** from ordinary-CM ∩ Ascent-0, not designed up front.
A compiler written now compiles to a moving target. This is also exactly how
Ascent-0 — the hard case, the one that proved most — was built: hand-authored IR,
no compiler.

One place the operator's framing is slightly overstated, recorded so I don't repeat
it as gospel: the compiler is straightforward as a *parser/serializer*, but its hard
part is **elaboration** — `DIRECTION.md` principle 2, "the surface hides boilerplate,
not obligations": `decide | Identified when unique` must *establish* the Core
condition, never assert it by token (#116). That is real design work. It does not
weaken the sequencing; it argues for it, since the elaboration can only be written
once the obligations are known.

The ladder is already named in `schema.cue` as `#StepKind`:
`mechanical | semantic_judgment | invoke_cm | oracle | transform`. Case order:
multi-step mechanical DAG (readiness + principled INCOMPLETE) → bounded collections
(map/fold, cardinality, per-item evidence) → `invoke_cm` (child CMs,
`#ChildReceiptEnvelope`) → `semantic_judgment` (the LLM effect boundary, refusals,
retained alternatives) → Ascent-0 through the same ABI = **freeze gate**. Compiler
after the target stops moving.

Harness fact — **a subagent cannot spawn subagents**. Topology constraint, load-bearing.

Attempted the operator's intended δ → γ-subagent → α/β-subagents nesting. γ, being a
subagent, had no way to launch α/β as subagents; it fell back to `claude -p` and then
could not wait on the background job properly, and while I took over it kept firing
*additional* α's into the same worktree — a three-way collision. Resolved by sending γ
an explicit stand-down.

The workable topology: **δ+γ from the main session, spawning α and β as subagents
directly.** Same firebreak, one less nesting level. Each cell gets its **own git
worktree**; two writers on one worktree is a collision. Resuming a cell by name keeps
its full context (used for repair rounds and close-outs) — this is how α fixed β's
findings without re-reading the whole issue.

Related harness trap I fell into: an Agent subagent's output file holds only its
**final result**, not live progress. I read 114 bytes as "stalled" and killed a
healthy α that was in fact reasoning correctly — and whose last thought had caught a
real contradiction in my own instructions (AC7 required creating a CI workflow that
my path-confinement clause forbade). **Do not twitch-monitor subagents; wait for the
completion signal.**

Standing rule adopted from β — ACs must gate what a cycle **authors**, not only what
it **emits**.

My #126 acceptance criteria required the emitted `MeasurementReceipt` to validate
against its contract. They never asked whether the **IR** — the artifact the cycle
*authored* — validated against anything. It did not: `cue vet … -d '#NormalizedCMIR'`
exited 1 for a missing `receipt_contract`, so the runtime was consuming a private
JSON shape that only it understood, and `coh-min`'s gate never asked. β verified
everything I put in the ACs, faithfully. **A gate that does not ask a question cannot
catch the answer.**

β's formulation, which I adopt verbatim as practice: *"ACs bound the approval gate but
not the search space — a reviewer whose search space is defined entirely by δ's ACs is
structurally incapable of catching a δ-side AC failure, which is the most consequential
error class in the process."* Its δ-side implication is now my rule: **name a
conformance gate for every artifact a cycle authors, not only those it emits.**

β also proposed two bounded, mechanical heuristics (~one command each) and applied
them in #127, where both earned their keep: a **schema census** over data artifacts in
the diff (found no unvetted authored artifact — a useful negative — and surfaced that
the workflow YAML has no in-repo validator at all), and a **harvest-parity check**
against a declared harvest source's gate set (retro-validated itself: Ascent-0's
`vet-ir` was precisely the missing target, and it surfaced that `make gate` does not
depend on `confine` while Ascent-0's `check` depends on `firewall`).

The CUE schema is **weaker than it looks**. Conformance ≠ runnability.

Found by α, independently reproduced and confirmed by β: of eight canonical
`#NormalizedCMIR` blocks, deleting `format`, `procedure`, or `result_contract`
**passes** `cue vet -d '#NormalizedCMIR'` — CUE unification makes an absent concrete
literal or open struct/list indistinguishable from an empty one. The runtime refuses
**8 of 8**.

So the two mechanisms are complementary, not redundant: the **schema owns exactness**
(closed top-level field set, shape of every block present — stray field or wrong type
rejected); the **runtime owns presence and fail-closed consumption**. β's framing to
keep: *"vets against `#NormalizedCMIR` is not equivalent to is a runnable CM IR until
that schema is tightened."*

Direct consequence for the operator's schema-first strategy: it is **not** "write JSON
against a fixed schema" — it is **co-design**, where each case teaches the schema what
a step must declare and the schema then pins every later case. The run-side of
`#NormalizedCMIR` is currently a stub (`steps: [...]`, `result_contract: {...}`) and
needs real teeth as the ladder advances. That is scoped work, and the reason
enforcement (`vet-ir` in the gate) had to land first.
