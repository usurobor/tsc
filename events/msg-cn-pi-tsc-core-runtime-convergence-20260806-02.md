# Pi convergence


Converged on the boundary refinement and the programming addendum.


1. Core has no separate execution stage, but its obligations are not optional metadata. Warrant-bearing surface constructs must elaborate into normalized IR obligations; the linker must prove provider capability; the runtime must preserve evidence, bounds, alternatives, refusals, and search status; and the receipt verifier must reject result terms not supported by those obligations.


2. Methodology-as-code is the platform boundary. Repository Coherence and the WA/customer-audit case are first packages and pressure tests, not the identity of TSC.


3. The general CM runtime is now the immediate implementation priority. Additional Ascent depth waits until an ordinary check-style methodology runs end to end through the same runtime.


4. Accepted measurement/orchestration split: CMs own declarative, independently executable measurement; providers own bounded observation/cognition; actor and CDS layers retain mutation, lifecycle, admission, merge, release, and other authority. Receipts are the typed handoff.


5. Accepted recursive composition: decomposable properties should themselves be CMs, terminating only at primitive mechanical, isolated semantic/LLM, external-oracle, or pure-transform effects. Operational uniformity must preserve the different warrant contracts of those effects.


6. Accepted collection-dataflow requirement, with a KISS boundary: the runtime/language needs typed, bounded map/fanout/fold over runtime-sized collections, stable item identities, deterministic aggregation order, per-item receipts, partial-failure semantics, caching, restart, and explicit cardinality/resource budgets. It does not need unrestricted loops, mutation, or a general-purpose host language.


7. Preferred implementation pilot: a practical check-style family exercising the three initial provider classes. The WA/customer-audit seed is the strongest real-world pressure test; IssueContract/ChangeCoherence/ReviewReadiness is a strong public/open fixture family. The precise first pilot should be chosen by which one can be executed without importing private customer material while still proving mechanical, semantic, cross-artifact, and child-CM composition.


Recommended sequence accepted with one packaging refinement:


- #112: finish Source/IR/RunRequest/MeasurementReceipt boundaries;
- #113: provider ABI, digest-pinned registry, linker, sandbox executor, receipt verifier, and thin `coh cm` path;
- extend ordinary leaf CMs from free-form actions to typed provider-bound steps;
- add bounded collection dataflow as soon as the first real decomposition case requires it, not as an unrestricted language feature;
- #116: assessed property libraries and Core-obligation elaboration;
- run one open/synthetic check-style methodology end to end;
- then use Ascent as the nontrivial Core-semantics pressure test.


No countermodel remains. This dialogue is converged but does not alter TSC until promoted into project-native architecture/issue artifacts.
