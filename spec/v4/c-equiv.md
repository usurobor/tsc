# C≡ v4.0.0-alpha.1 — Typed Articulation and Generative Unfolding

**Version:** 4.0.0-alpha.1
**Date:** July 2026
**Status:** Draft foundation; non-normative until conformance and review
**Supersession:** Does not yet supersede C≡ v3.1.0

---

## 0. Scope

C≡ v4 is a formal grammar for **typed articulation**:

> how a concrete state unfolds as a relational event and a lawful continuation.

It formalizes:

- coherer, cohering, and cohered as dependent roles in one event;
- concrete open generators;
- repeated and compositional unfolding;
- conditional final behavioral semantics;
- presentation-sensitive and behavior-sensitive equivalence;
- the structural information that later coherence measurement must retain.

It does **not** define:

- one universal coherence scalar;
- a universal threshold;
- a fixed number of observations or views;
- an unrestricted symmetry among semantic roles;
- that reality is a final coalgebra;
- that final coalgebras exist for every chosen system functor or carrier category.

### 0.1 Migration thesis

Earlier C≡ versions used a free ternary term:

```text
tri(T₁,T₂,T₃)
```

and then evaluated it by commutative folds. The syntax could display shape, but the evaluators erased arrangement and depth before coherence was assessed.

v4 replaces the free semantic triple with a typed relational event and treats scalarization as a downstream, explicitly justified operation.

## 1. Base formulation in `Set`

The exact base kernel is stated first in `Set`. A methodology MAY instantiate an appropriate metric, measurable, topological, enriched, probabilistic, or other category, but MUST then state its products, exponentials or alternative open-system construction, behavioral semantics, and existence assumptions.

### 1.1 Pole types and relation family

Let:

```text
P       declared pole universe
Rel     P × P → Set
```

`P` MAY be a tagged disjoint union of heterogeneous pole types. The tags and the relation family preserve which source/result combinations are well formed.

For `s : P` and `o : P`, an inhabitant:

```text
φ : Rel(s,o)
```

is a typed cohering relation between those poles.

### 1.2 Articulation event

Define the dependent articulation type:

```text
Art := Σ(s : P). Σ(o : P). Rel(s,o)
```

An event is written:

```text
art(s, φ, o)
```

where `φ : Rel(s,o)`.

The three roles are inseparable but not interchangeable:

- `s` is a source pole;
- `o` is a result pole;
- `φ` is dependent on both.

A bare triple `(s,φ,o)` whose middle component is not typed by the two poles is not a C≡ articulation.

### 1.3 Unity migration

Earlier versions said that a designated center position carries unity.

v4 states instead:

> The middle role carries the dependent cohering relation. Unity is not stored in a component; unity belongs to the whole well-typed event and, recursively, to the concrete generator that lawfully continues it.

The earlier intuition was correct that the middle differs in kind and incorrect to model unity as a freely permutable occupant.

## 2. Open generative presentations

### 2.1 State and input

Let:

```text
X       concrete generator state/presentation type
I       exogenous input/query/intervention type relative to the declared boundary
```

A deterministic open generator is:

```text
c : X × I → Art × X
```

When exponentials are available, equivalently:

```text
c : X → (Art × X)^I
```

For state `x` and external input `i`:

```text
c(x,i) = (a,x')
```

means:

1. the generator emits typed articulation event `a`;
2. the same unfolding continues as state `x'`.

### 2.2 Query provenance

Every use of the kernel MUST declare:

```text
query_mode = exogenous | endogenous | mixed
```

- **exogenous:** the relevant query is supplied through `I`;
- **endogenous:** the query is generated within `X` or represented within `Art`;
- **mixed:** both occur and their ownership is explicitly separated.

A query generated by the candidate system cannot be described as held out merely because its output was not previously observed.

### 2.3 Repeated unfolding

Given an input history:

```text
i₀,i₁,...,iₙ₋₁
```

repeated application yields:

```text
x₀ --i₀/a₀→ x₁ --i₁/a₁→ ... --iₙ₋₁/aₙ₋₁→ xₙ
```

The history retains both:

- the emitted articulation events;
- the concrete intermediate states or a declared projection of them.

The intermediate presentation MUST NOT be erased when later obligations depend on complexity, mechanism, intervention, or path history.

## 3. Final behavioral semantics

### 3.1 System functor

In the base deterministic `Set` formulation, define:

```text
F_I(Y) := (Art × Y)^I
```

Then `c : X → F_I(X)` is an `F_I`-coalgebra.

### 3.2 Conditional finality

If a final `F_I`-coalgebra exists, write it as:

```text
ζ : νF_I → F_I(νF_I)
```

For every concrete coalgebra `c : X → F_I(X)`, finality gives a unique behavior map:

```text
beh_c : X → νF_I
```

such that:

```text
ζ ∘ beh_c = F_I(beh_c) ∘ c
```

This commuting law is the exact compatibility condition between a concrete presentation and its complete behavioral semantics.

### 3.3 Lambek consequence

By Lambek’s lemma, the final structure map is an isomorphism:

```text
ζ : νF_I ≅ F_I(νF_I)
```

Therefore, at the final behavior object:

> complete behavior and input-indexed one-step articulation-plus-continuation are mutually recoverable.

This theorem is conditional.

It does **not** imply:

- `c` is an isomorphism;
- the concrete system is final;
- the selected `F_I` is empirically correct;
- every methodology has a set-sized final coalgebra;
- reality as a whole has been proved to be a final coalgebra.

### 3.4 Existence obligation

A methodology invoking `νF` MUST identify one of:

1. a theorem establishing the relevant final coalgebra in the declared category;
2. an explicit finite-horizon behavior construction;
3. a declared approximation or completion with stated loss.

If none is supplied, the methodology may reason about concrete unfoldings but MUST NOT claim final behavioral semantics.

### 3.5 Final semantics is a quotient

`beh_c` identifies concrete states that are behaviorally equivalent under the selected inputs and observations.

This loss is intentional for behavioral semantics and unacceptable as a universal replacement for the presentation.

The normative evidence therefore retains:

```text
(X,c)
beh_c or its finite approximation
(νF_I,ζ), when available
the commuting/approximation witness
```

Complexity, implementation, causal, and intervention claims are evaluated on the presentation and cannot be reconstructed from the final behavior point alone.

## 4. Composition and shape

### 4.1 Typed composition

When `Rel` is equipped with identity and partial composition satisfying the declared category/path laws, and endpoints match:

```text
art(s, φ, t)
art(t, ψ, u)
```

compose to:

```text
art(s, ψ ∘ φ, u)
```

The composed arrow MAY be used as a derived view, but the path witness:

```text
[φ,ψ]
```

MUST remain available whenever path length, accumulated tolerance, intervention history, or intermediate identity is relevant.

### 4.2 No premature quotient axiom

A reduction:

```text
structured evidence → summary
```

is valid only when a theorem or declared oracle establishes that the summary is sufficient for the exact downstream judgment.

Convenience, bounded output size, and aggregate symmetry are not sufficiency proofs.

### 4.3 Commutative-fold blindness theorem

Let `(M,⊗,1)` be a commutative monoid, assign each atom label `a` a value `w_a ∈ M`, and define a tree evaluator by:

```text
E(e) = 1
E(a) = w_a
E(tri(t₁,t₂,t₃)) = E(t₁) ⊗ E(t₂) ⊗ E(t₃)
```

Then `E(t)` factors through the finite multiset of atom labels in `t`.

Therefore `E` cannot distinguish:

- child arrangement;
- grouping;
- nesting depth;
- path order;
- node contribution;
- positional role.

If all atoms share one weight, it factors further through atom count.

### 4.4 Consequence for v3 evaluators

The v3 α evaluator is a capped atom count.

The v3 γ evaluator satisfies, for `n` atoms:

```text
E_γ(t) = (n, 2^n - 1)
```

so α factors through γ and neither sees tree shape.

The v4 foundation records this as a negative theorem: an evaluator claiming shape, depth, process order, or compositional history MUST NOT be merely an associative commutative fold over leaves.

### 4.5 Shape-sensitive examples

Shape sensitivity does not require unrestricted noncommutativity.

For example:

```text
d(e) = 0
d(a) = 0
d(tri(x,y,z)) = 1 + max(d(x),d(y),d(z))
```

is symmetric in child presentation yet distinguishes nesting because the node contributes explicitly and the recurrence is not a flattening monoid fold.

C≡ v4 does not prescribe one universal shape evaluator. It prescribes the information that a claimed evaluator must retain.

## 5. Equivalence and symmetry

### 5.1 Presentation equivalence

Two concrete presentations may be declared equivalent when a role-preserving isomorphism transports:

- state;
- input ownership;
- articulation events;
- transition structure;
- declared complexity representation.

The methodology defines the exact equivalence and proves or tests its invariants.

### 5.2 Behavioral equivalence

When final semantics exists, states may be behaviorally equivalent when their behavior maps coincide, or approximately equivalent under a declared behavioral pseudometric.

Behavioral equivalence is indexed by the available input/query family. Widening the input family may distinguish states previously equivalent.

### 5.3 Role-preserving gauge

Physical serialization slots, variable names, or diagram layout are gauge when role labels and dependent typing move with them.

The semantic roles:

```text
source / coherer
relation / cohering
result / cohered
```

are not generally permutable.

No unrestricted `S₃` action on these semantic roles is a C≡ invariant.

A methodology MAY declare a domain symmetry, but MUST identify:

- the action;
- the objects and arrows it acts on;
- which roles are preserved or exchanged;
- the invariant or equivariant output;
- the test that would falsify the symmetry claim.

## 6. Silence, identity, and source proximity

### 6.1 No universal empty-wholeness score

C≡ v4 has no universal term `e` satisfying:

```text
e ~ tri(e,e,e)
```

and no axiom:

```text
coherence(e) = 1
```

A methodology may define:

- an identity relation `id_s : Rel(s,s)`;
- a silent/no-observation event;
- a source or quiescent state;
- a source-proximity measure.

These are typed, methodology-scoped objects.

### 6.2 Distinct constructs

A source-proximity measure may legitimately assign its maximum to an unarticulated or quiescent state.

It MUST NOT be named coherence merely because both use `[0,1]`.

C≡ defines articulation structure. TSC Core defines the obligations under which articulation is judged coherent.

## 7. Foundation axioms

### F1 — Typed articulation

`art(s,φ,o)` is well formed only when `φ : Rel(s,o)`.

### F2 — Dependent middle

The cohering relation is indexed by both poles and is not a freely exchangeable peer.

### F3 — Unity of event

Unity belongs to the complete typed event and its lawful continuation, not to a distinguished storage position.

### F4 — Generative continuation

A concrete articulation process exposes both an event and a continuation state.

### F5 — Open-boundary declaration

Every empirical instantiation declares which inputs are exogenous relative to the tested boundary and which queries are generated internally.

### F6 — Presentation preservation

Concrete presentation and behavioral semantics are both retained when downstream claims depend on presentation-sensitive facts.

### F7 — Conditional finality

A final coalgebra or declared approximation is used only with an existence/approximation witness.

### F8 — No premature quotient

No scalar or equivalence quotient replaces structured evidence without a sufficiency argument for the downstream claim.

### F9 — Scoped symmetry

Only role-preserving gauge or explicitly declared domain symmetries are admissible.

### F10 — No fixed observation cardinality

Triadicity is the dependent role structure of an articulation event, not a claim that every phenomenon requires exactly three observations.

### F11 — Shape honesty

An evaluator claiming shape, nesting, or order must distinguish declared equal-leaf-multiset counterexamples.

### F12 — Construct separation

Articulation, source proximity, and coherence are not identified by default.

## 8. Minimal exact kernel

```text
P                          pole universe (possibly tagged)
Rel : P × P → Set         dependent relation family
Art := Σs.Σo.Rel(s,o)     articulation event
X                          concrete state/presentation
I                          exogenous input relative to boundary
c : X × I → Art × X       open generator
F_I(Y) := (Art × Y)^I     system functor, when available
ζ : νF_I → F_I(νF_I)     final behavior structure, if it exists
beh_c : X → νF_I          unique behavior map
ζ ∘ beh_c = F_I(beh_c) ∘ c
```

The complete normative object is not one corner of this diagram. It is the typed presentation and the witnessed relation among its corners.

## 9. Migration from C≡ v3

| v3 object | v4 status |
|---|---|
| `tri(T,T,T)` | retained only as untyped legacy syntax or visualization; not the semantic kernel |
| center carries unity | migrated: center/relation is dependent; unity belongs to whole event |
| `e ~ tri(e,e,e)` | removed from universal foundation |
| α capped atom count | may remain an articulation-extent proxy, not an independent coherence axis |
| β root occupancy | may remain a coarse presentation projection, not a relational atlas |
| γ count-derived “depth” | withdrawn as depth claim |
| `S₃` over positions/axes | replaced by typed role-preserving gauge and declared symmetries |
| inverse evaluator scores | renamed source-proximity if retained |
| `C_Σ` foundation aggregate | removed from C≡; optional receipt summary belongs downstream |
| unrestricted dyadic impossibility | withdrawn or requires a separately proved restricted encoding theorem |
