# C≡ v4 — Typed Articulation and Generative Unfolding

**Version:** 4.0.0
**Status:** Draft
**Artifact:** Normative foundation

## 0 · Governing question

> What is the smallest formal structure that represents one process articulating as distinguishable poles through a relation, and continuing to articulate?

C≡ answers this question with a typed articulation event and an open generator. It defines articulation, composition, unfolding, behavior, and equivalence. It does not define a universal coherence score.

---

## 1 · Typed articulation

### 1.1 Pole universe

Let `P` be a type of poles.

A pole is a role-bearing endpoint in an articulation. A pole need not be a material object. It may represent a state, context, observation, agent, pattern, boundary, or other domain-specific endpoint.

### 1.2 Relation family

Let:

```text
Rel : P × P → Set
```

For `s,o : P`, an inhabitant:

```text
φ : Rel(s,o)
```

is a cohering relation from `s` to `o`.

The relation is dependent: its type is indexed by both endpoints. A relation cannot be moved to different endpoints unless a declared transport makes the move well typed.

### 1.3 Identity and composition

For every `s : P`, there is an identity relation:

```text
id_s : Rel(s,s)
```

For:

```text
φ : Rel(s,o)
ψ : Rel(o,u)
```

there is a composite:

```text
ψ ∘ φ : Rel(s,u)
```

Composition satisfies:

```text
id_o ∘ φ = φ
φ ∘ id_s = φ
χ ∘ (ψ ∘ φ) = (χ ∘ ψ) ∘ φ
```

The pole universe with these relations forms a small category of articulations.

### 1.4 Articulation event

Define:

```text
Art := Σ(s : P). Σ(o : P). Rel(s,o)
```

Write an event as:

```text
art(s, φ, o)
```

or:

```text
s --φ→ o
```

The event has three roles:

- `s` — coherer or source pole;
- `φ` — cohering relation;
- `o` — cohered or result pole.

These roles are inseparable and non-interchangeable. The relation is not a third substance beside two things. It is the typed dependence through which the poles belong to one event.

### 1.5 Unity

Unity belongs to the complete well-typed event:

```text
art(s, φ, o)
```

No component stores unity by itself. The relation carries the dependence; the whole event carries the one articulation.

### 1.6 Event projections

Every event `a : Art` has projections:

```text
src(a) : P
dst(a) : P
rel(a) : Rel(src(a), dst(a))
```

The canonical dependent-sum representation is lossless:

```text
a = art(src(a), rel(a), dst(a))
```

## 2 · Paths and diagrams

### 2.1 Path

A path is a finite composable sequence:

```text
s_0 --φ_0→ s_1 --φ_1→ ... --φ_(n-1)→ s_n
```

Its composite is:

```text
φ_(n-1) ∘ ... ∘ φ_1 ∘ φ_0 : Rel(s_0,s_n)
```

A path retains its intermediate poles and relations. The composite alone is not a sufficient replacement when a later claim depends on order, mechanism, complexity, or local error.

### 2.2 Diagram

A diagram is a typed collection of poles, relations, and composable paths.

A diagram may contain:

- several observations of one process;
- alternative correspondences;
- temporal transitions;
- interventions and responses;
- nested or concurrent articulations;
- unresolved relations.

The number of observations is not fixed. Triadicity belongs to each typed event, not to the cardinality of the diagram.

### 2.3 Commutation

Two paths with the same endpoints commute when their composites agree:

```text
p ≡ q
```

An approximate methodology may replace equality with a declared metric and tolerance law. Approximation does not remove the obligation to retain the compared paths.

## 3 · Open generators

### 3.1 State and external input

Let:

```text
X : Set
I : Set
```

`X` is the concrete generator state. `I` is the input, query, or intervention supplied from outside the declared generator boundary.

### 3.2 Generator

A deterministic open generator is:

```text
c : X × I → Art × X
```

For:

```text
c(x,i) = (a,x')
```

one application of `c`:

1. emits articulation event `a`;
2. continues as state `x'`.

A pointed generator presentation is:

```text
G := (X, I, c, x_0)
```

where `x_0 : X` is the initial or current state under examination.

### 3.3 Query ownership

Every generator presentation declares:

```text
query_mode = exogenous | endogenous | mixed
```

- `exogenous` — the relevant query enters through `I`;
- `endogenous` — the query is generated within `X` or emitted in `Art`;
- `mixed` — both occur and the boundary between them is explicit.

A query generated by the candidate process is not an independent intervention merely because its answer was not recorded before.

### 3.4 Unfolding

Given inputs:

```text
i_0, i_1, ..., i_(n-1)
```

repeated application yields:

```text
x_0 --i_0/a_0→ x_1 --i_1/a_1→ ... --i_(n-1)/a_(n-1)→ x_n
```

Define the finite unfolding:

```text
run_n(G, i_0...i_(n-1))
  = (a_0...a_(n-1), x_0...x_n)
```

The unfolding retains both emitted events and concrete states unless a declared quotient has been proved sufficient for the downstream claim.

### 3.5 Reflexivity

A generator is reflexive when its emitted events or successor states alter the conditions of later articulation.

Reflexivity is represented by recurrence through `X`; it does not require the generator to be closed to external input.

## 4 · Coalgebraic behavior

### 4.1 System functor

For fixed `Art` and `I`, define:

```text
F_I(Y) := (Art × Y)^I
```

Currying identifies the generator with an `F_I`-coalgebra:

```text
c : X → F_I(X)
```

### 4.2 Final behavior

When a final `F_I`-coalgebra exists, write:

```text
ζ : νF_I → F_I(νF_I)
```

For every concrete coalgebra `c : X → F_I(X)`, finality gives a unique map:

```text
beh_c : X → νF_I
```

satisfying:

```text
ζ ∘ beh_c = F_I(beh_c) ∘ c
```

This commuting square states that concrete unfolding and behavioral interpretation agree at every step.

### 4.3 Lambek law

The final structure map is an isomorphism:

```text
ζ : νF_I ≅ F_I(νF_I)
```

At final behavior, the whole behavior is mutually recoverable with one input-indexed articulation step and its lawful continuation.

The isomorphism belongs to the final behavior object. A concrete generator is not presumed final or invertible.

### 4.4 Finite behavior

When final behavior is unavailable, unnecessary, or outside the chosen category, a methodology may use a finite horizon:

```text
beh_c^n : X → B_n
```

The methodology must declare:

- the horizon `n`;
- the information retained in `B_n`;
- the equivalence induced by the truncation;
- the claims that remain valid at that horizon.

Finite approximation must not be described as final semantics.

### 4.5 Existence obligation

A methodology invoking `νF_I` must identify:

- the carrier category;
- the functor;
- the existence theorem or construction;
- all boundedness, accessibility, measurability, topology, metric, or cardinality assumptions.

If the obligation is not met, the methodology must use an explicit approximation.

## 5 · Equivalence

### 5.1 Presentation equivalence

Two pointed presentations:

```text
G  = (X, I, c, x_0)
G' = (X', I, c', x'_0)
```

are presentation-isomorphic when there is a bijection or declared isomorphism:

```text
h : X ≅ X'
```

with:

```text
h(x_0) = x'_0
```

and:

```text
(id_Art × h) ∘ c = c' ∘ (h × id_I)
```

### 5.2 Behavioral equivalence

When final behavior exists, states are behaviorally equivalent when:

```text
beh_c(x) = beh_c(y)
```

in the final behavior space.

Behavioral equivalence intentionally forgets presentation details that do not change observable behavior.

### 5.3 Input-indexed equivalence

For a declared input family `J ⊆ I*`, two presentations are `J`-equivalent when they agree on all tested histories in `J` under the methodology’s observation rule and tolerance.

Identifiability is always indexed by the declared input or intervention family. It is never absolute.

### 5.4 Presentation retention

A behavior point cannot replace its presentation when a claim depends on:

- mechanism;
- implementation;
- complexity or code length;
- resource cost;
- causal response;
- intervention boundaries;
- migration or provenance.

The normative evidence retains both the presentation and its behavior map.

## 6 · Quotients and structural sufficiency

### 6.1 No premature quotient

A quotient may replace structured evidence only when the methodology proves that the quotient is sufficient for the exact downstream decision.

Without such a proof, the quotient is a summary and the structured source remains normative.

### 6.2 Commutative-fold blindness

Let `T(A)` be a finite rooted tree algebra whose leaves are labeled by `A`. Let:

```text
E(leaf(a)) = w_a
E(node(t_1,...,t_k)) = E(t_1) ⊗ ... ⊗ E(t_k)
```

where `(M,⊗,1)` is an associative commutative monoid.

Then `E` factors through the finite multiset of leaf labels. It cannot distinguish:

- sibling order;
- grouping;
- path shape;
- depth;
- internal-node identity.

Therefore an evaluator claiming shape, depth, order, or path sensitivity must retain internal-node structure or use another construction whose sufficiency is proved.

### 6.3 Scalar summaries

A scalar may summarize a structure after the relevant categorical status has been established.

A scalar cannot, by itself, distinguish:

```text
no realization
several realizations
one identified realization
search incomplete
lawful termination
law violation
```

## 7 · Symmetry

### 7.1 Presentation symmetry

A serialization may reorder stored fields when role labels, endpoints, and relation typing move with them and the decoded event is unchanged.

This is presentation gauge.

### 7.2 Semantic role symmetry

Source, relation, and result are not freely permutable semantic peers.

A semantic permutation is valid only when a declared isomorphism transports:

- pole roles;
- relation types;
- composition;
- generator behavior;
- observation meaning.

No unrestricted `S₃` action is assumed.

### 7.3 Declared domain symmetry

A methodology may declare additional symmetries. Every such symmetry must state:

- what it acts on;
- which structure it preserves;
- whether it is exact or approximate;
- how the receipt verifies it.

---

## 8 · Foundation conformance

A C≡ implementation is conforming when it can:

1. reject an event whose relation is not typed by its endpoints;
2. compose only relations with matching intermediate poles;
3. retain paths and intermediate states when later claims depend on them;
4. distinguish presentation equivalence from behavioral equivalence;
5. declare the exogenous input boundary;
6. emit finite behavior honestly when final behavior is unavailable;
7. state and verify every finality claim;
8. refuse an unsupported quotient as normative evidence;
9. preserve semantic roles through serialization and transport;
10. expose enough structure for a Core receipt to reproduce the unfolding claim.

## 9 · Canonical kernel

```text
P                         pole type
Rel : P × P → Set        dependent relation family
Art := Σs.Σo.Rel(s,o)    typed articulation event

X                         concrete state
I                         exogenous input relative to the declared boundary
c : X × I → Art × X      open generator
G := (X,I,c,x_0)         pointed presentation

F_I(Y) := (Art × Y)^I    system functor
ζ : νF_I → F_I(νF_I)    final behavior structure, when it exists
beh_c : X → νF_I         unique behavior map

ζ ∘ beh_c = F_I(beh_c) ∘ c
```

C≡ ends at typed articulation and lawful unfolding. TSC Core begins with the evidential question of whether a declared generator is warranted by observations.
